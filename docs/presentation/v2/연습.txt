1페이지
안녕하십니까, AI 여행 동행자 앱 Polylog 발표를 시작하겠습니다.
저희 앱의 비전은 길을 잃어도 이야기는 잃지 않도록 입니다.
비싼 돈과 귀중한 시간을 투자해서 여행을 갔는데 예상치 못한 일이나 계획으로 고생하지 않도록 하기 위한 앱입니다.
시간 관계상 불편사항 4가지를 어떻게 해결했는지 구현영상과 같이 보시겠습니다.

2페이지
1. 먼저 계획 단계인데요, 여행이라 함은 낯선 곳을 방문하는 것에서 즐거움을 찾는다고 생각하는데 낯선 곳의 정보를 얻기란 쉽지 않죠? 이 부분을 AI와 대화를통해 일정을 계획함으로써 불편함을 해소하려 했습니다. [영상 1분]
2. 일정대로 흘러가지 않는 경우도 있습니다. 이럴 때 gps 기반으로 주변 리뷰들을 분석해 제공해주는 서비스 입니다.
[영상 20초]
3. 외국어 메뉴판에 사진도 없다면 뭐가 나올지 불안하죠? 모든 언어를 분석해 어떤 메뉴인지 검색도 가능한 기능입니다. [영상 20초]
4. 영수증을 읽어 지출 분석도 해주는 모습입니다. [영상 25초]

3페이지
이런 기능들을 어떻게 만들었는지 궁금하실텐데요. 이런 아키텍처를 통해 구현했습니다.
플러터를 바탕으로 구현을 했으며, 모든 기능은 사용자의 채팅, 사진 업로드 등의 요청으로 시작 됩니다.
모든 기능들은 같은 흐름으로 진행되는데 구글OAuth로 로그인 유무를 확인하며 확인 이 완료된 요청만 각 알맞는 함수를 호출하게 됩니다.
이 앱은 AWS인프라를 사용해 서버리스 구조를 활용했는데요. 때문에 학생인 저에게 비용부담이 최소화 되도록 구현했습니다. 각 함수 처리 흐름에 필요한 API를 사용해 최종적으론 사용자에게 출력하고 저장할 데이터는 DynamoDB에 저장되는 형식을 갖추었습니다.

4페이지
여러 고난이 있었지만 그 중에서 메뉴 기능에 대해 잠깐 설명 드리고 넘어가겠습니다.
처음엔 메뉴를 분석해서 사용자의 선호도와 알러지를 반영해 추천하는 기능을 넣으려 했습니다. 하지만  Textract라고 글을 인식하는 서비스가 라틴어 기반만 인식이 되어 한중일 언어는 번역이 어려웠고 이 부분을 분기 처리해서 구현하려 했지만 구글 렌즈가 더 성능이 좋아 구현했던 기능을 포기하고 과감히 구글렌즈로 위임했습니다.

5페이지
wbs를 간단히 정리한 내용인데요. 첫주는 아이디어 도출과 인프라 구축에 힘을 썼고, 둘쨋 주 부터 본격적으로 메인, 서브 기능들을 완성해 갔습니다. 셋 쨋주엔 버그들과 UI 부분을 수정했고 최종 넷 쨋주에 발표준비를 했습니다.

6페이지
-개발 환경은 플러터, 인프라 구축과 함수들은 AWS SAM을 이용했으며, 권한 때문에 배포는 직접 스크립트로 CloudShell을 이용해 배포 하였습니다.
-빌드 배포 과정은 로컬 컴퓨터에서 Ai로 코드 작업을 하고 각 기능 단위 테스트를 거친 뒤 git에 올렸고요.
CloudShell에서 pull 받아 sam 빌드와 배포를 진행 했습니다.
-테스트는 로컬에서 test-agemt AI를 활용해 단위 테스트를 진행했고 통합 검증은 AI가 너무 느려서 제가 직접 실기기로 테스트 해보았습니다.
-문서는 Readme로 이 앱이 무엇인지, ADR로 왜 이 기술들을 사용했는지, AGENTS로 어떻게 설치하고 사용하는지 명시해 두었습니다.
