# 도커 이사 계획

> 배경: 학교 제공 AWS 계정은 졸업 후 모든 자원이 삭제된다. 포트폴리오를 계속 시연할 수 있도록 백엔드를 Docker로 옮긴다.
> 작성일: 2026-10-17

## 현재 AWS에 묶인 부분

| AWS 자원 | 코드에서 쓰는 곳 | Docker에서 바꿀 것 |
|---|---|---|
| API Gateway + Lambda 6개 | 핸들러마다 `lambda_handler(event, context)` | FastAPI 서버 하나가 요청을 Lambda 이벤트 형식으로 바꿔 기존 핸들러를 그대로 호출 |
| Lambda Authorizer | `authorizer/app.py` (Google 토큰 검증) | 같은 서버의 미들웨어에서 authorizer 핸들러를 호출하고, 결과를 `requestContext.authorizer`에 넣음 |
| DynamoDB 테이블들 (schedules, chats, trips, users, receipts, menus) | `boto3.resource("dynamodb", region_name=...)` | **DynamoDB Local** 컨테이너 사용. boto3가 `AWS_ENDPOINT_URL_DYNAMODB` 환경변수를 읽으므로 **코드 수정 없음** |
| S3 `polylog-media` | receipt, menu에서 이미지 저장 | **대체하지 않음.** MinIO 공개 이미지가 배포 중단돼 받을 수 없고, 앱은 원본 사진을 다시 쓰지 않으며 저장 실패는 핸들러가 무시한다 |
| LiteLLM 게이트웨이 | `LLM_BASE_URL/v1/chat/completions`, 모델 이름 `bedrock-haiku`·`bedrock-sonnet` | 학교에서 준 키라면 이것도 사라진다. **LiteLLM 컨테이너를 직접 띄우고** 본인 Anthropic API 키로 같은 이름(`bedrock-haiku`·`bedrock-sonnet`)을 매핑하면 **코드 수정 없음** |
| Google Places, 환율 API | 외부 API | 그대로 쓰고 키만 `.env`로 옮김 |

결국 새로 만들 파일은 **어댑터 서버 하나(약 50~80줄)와 Docker 설정 파일들**뿐이고, 핸들러 6개는 손대지 않는다.

## 단계별 계획

### 0단계: 졸업 전에 백업 (가장 급함, 계정이 살아 있을 때만 가능)
1. **CloudShell `~/.bashrc`의 키 5종을 내 PC로 옮기기.** CloudShell 홈 폴더도 계정과 함께 사라진다. 옮길 것은 Places 키, Google Client ID, 환율 키, LLM URL/키.
2. **테이블 스키마 기록:** 테이블마다 `aws dynamodb describe-table`을 실행해 키 구조를 저장한다. ADR-014·015에 대부분 있지만 실제 값으로 확인해 두는 게 안전하다.
3. **(선택) 데모 데이터 백업:** `aws dynamodb scan`으로 JSON을 받고, `aws s3 sync s3://polylog-media ./backup`으로 이미지를 받는다. 포트폴리오 시연용 데이터가 필요할 때만.
4. **LiteLLM 키의 출처 확인:** `docs/LITE LLM 키 사용 안내 가이드.pdf`를 보면 학교 키로 보인다. 맞다면 본인 Anthropic 또는 OpenAI 호환 API 키를 미리 준비한다.

### 1단계: 로컬 Docker 구성
```
docker/
  server.py            # FastAPI: 라우트 → lambda_handler 호출 + authorizer 미들웨어
  Dockerfile           # python:3.12-slim + boto3, fastapi, uvicorn
  litellm-config.yaml  # bedrock-haiku / bedrock-sonnet → 실제 모델 매핑
  init-resources.py    # DynamoDB Local 테이블 생성
docker-compose.yml     # api, dynamodb-local, litellm (+ 1회성 init)
.env.example           # 키 목록 (실제 .env는 gitignore)
```
- 라우트는 template.yaml과 같게 맞춘다: `GET /health`, `POST /recommend`, `GET·POST /schedule`, `POST /planner`, `POST /receipt`. `/menu`는 앱이 호출하지 않으므로(ADR-018) 빼도 된다.
- 실행은 `docker compose up` 한 번이고, 그 뒤 기존 curl 명령으로 확인한다.

### 2단계: 앱 연결
- `app/lib/core/api/dio_client.dart`에 하드코딩된 baseUrl을 `String.fromEnvironment('API_BASE_URL')`로 바꾼다. `GOOGLE_CLIENT_ID`와 같은 방식이고, 빌드할 때 `--dart-define`으로 주입한다.
- Google OAuth Client ID는 학교 계정이 아니라 본인 Google Cloud 프로젝트 것이면 그대로 쓸 수 있다. 확인 필요.

### 3단계: 외부 공개 (필요할 때만)
- 면접 시연처럼 폰에서 접속해야 할 때는 **Cloudflare Tunnel**을 쓴다. 무료이고 HTTPS가 자동으로 붙어서 Android의 http 차단 문제도 없다. 내 PC에서 `docker compose up`과 터널만 켜면 된다.
- 계속 켜 둬야 한다면 무료 VM(Oracle Cloud Free Tier 등)에 같은 compose 파일을 올린다.

### 4단계: 포트폴리오 정리
- README에 "원래 구조는 AWS 서버리스, 현재는 Docker로 재현 가능"이라는 섹션과 `docker compose up` 실행 방법을 추가한다.
- 데모 영상(`docs/demo-*.mp4`)과 발표 자료는 이미 git에 있어서 따로 할 일이 없다.
- (선택) `docker compose` 이미지를 Docker Hub나 GHCR에 올려 두면 `pull` 한 번으로 실행할 수 있다.

## 확인이 필요한 것
1. **LiteLLM 키가 학교 제공인지:** 학교 키라면 본인 LLM API 키가 필요하고, 사용량만큼 비용이 든다.
2. **Google Cloud 프로젝트(Places 키, OAuth)가 개인 계정 것인지:** 학교 계정이라면 다시 발급해야 한다.
3. **목표 수준:** "내 PC에서 `docker compose up`으로 시연"까지면 1·2단계로 충분하다. 항상 켜진 서버가 필요하면 3단계까지 간다.
